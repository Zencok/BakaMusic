# AMLL 播放背景

## 渲染设计

普通播放背景使用全屏连续采样场，而不是将封面 UV 映射到随机变形网格。固定网格上的局部小位移不易察觉，折叠区域还可能出现明显的几何分界。现在以屏幕坐标驱动两层缓慢旋转、漂移和扭曲的封面色域，再进行柔化和混合。

采样坐标采用连续正弦映射，保持在纹理内部，避免硬裁切或重复平铺形成边界。保留既有封面降采样、模糊、半浮点中间纹理以及最终抗色带抖动。手动控制模式仍保留网格、控制点及上游相关接口。

这是对柔和动态流光的近似实现，不是 Apple Music 私有渲染算法的复刻。上游同步时应保留本地 shader 和渲染分支，不能仅恢复原网格绘制调用。

## 调度与性能

- 目标为 60 FPS；限帧允许 0.5 ms 的刷新时间误差，避免 60 Hz 下隔帧绘制。
- 第一次绘制及恢复时重新锚定动画时钟；单次增量上限为 100 ms，避免长时间隐藏后突然跳变。
- 中间画布最长边限制为 960 像素，其余尺寸按比例缩放，减少多次模糊的 GPU 成本。
- 背景在详情页可见时持续流动，不与歌曲暂停状态绑定；详情关闭或窗口隐藏时停止绘制。
- 系统启用减少动态效果时，在封面过渡完成后停留在静态帧；偏好改变或窗口恢复时重新同步。

## 验证

运行 TypeScript、只读 ESLint、`npm test`，以及 package/smoke 验证。运行时性能回归覆盖刷新误差、暂停恢复、零帧率、静态模式，以及普通模式全屏绘制和手动网格模式。

视觉验证需要使用同一张多色封面比较连续数秒的画面，检查色域是否有可见位移、边界是否平滑，并检查切换封面、隐藏恢复及减少动态效果行为。单色封面的变化天然较小，不能作为动画停止的判断依据。
